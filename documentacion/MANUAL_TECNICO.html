2.2. Tablas Complementarias del Sistema

  • rounds: Control de ciclos mensuales de inspección (apertura, avance y cierre).
  • inspections: Registro inmutable de cada control con inspector, duración, flags antifraude y geolocalización opcional.
  • cases: Seguimiento de no conformidades con cálculo de antigüedad en días corridos y extintor temporal de reemplazo.
  • audit_logs: Bitácora de trazabilidad de cambios en la ficha técnica (quién, cuándo y qué campo cambió).

3. Seguridad, Antifraude y Resiliencia

Mecanismo Antifraude Liviano
El sistema cronometra el tiempo exacto entre la apertura de la ficha del extintor y el guardado final. Si la duración es menor a 5 segundos, se registra el flag is_suspicious = 1 para auditoría posterior, sin bloquear al inspector en campo para no demorar la operación. 
// Protección contra MIME type sniffing y clickjacking (server/index.js)
app.use((req, res, next) => {
  res.setHeader('X-Content-Type-Options', 'nosniff');
  res.setHeader('X-Frame-Options', 'SAMEORIGIN');
  res.setHeader('X-XSS-Protection', '1; mode=block');
  res.setHeader('Referrer-Policy', 'strict-origin-when-cross-origin');
  next();
});

3.4. Motor de Escaneo QR, Redirección y Tolerancia a Fallos

Para garantizar cero bloqueos en obra tanto en celulares iOS como Android:

  • Redirección 302 Corta: Los códigos QR contienen enlaces a /m/:publicId que transfieren de inmediato a /?code=MF-XXX#check.
  • Base URL Dinámica: El backend detecta encabezados de proxy inverso (x-forwarded-host, x-forwarded-proto) resolviendo automáticamente el dominio activo sin depender de valores estáticos en base de datos.
  • Tolerancia en Búsqueda: GET /api/extinguishers/:idOrCode soporta URLs completas, códigos sin prefijo (auto-padding a 3 dígitos), minúsculas y mayúsculas.
  • React Error Boundary: Envuelve la interfaz completa para aislar errores imprevistos y ofrecer recarga inmediata sin pantalla en blanco.
  • Depuración de Cola 409: Los registros offline con respuesta 409 Conflict (ya controlados en la ronda) se purgan automáticamente de IndexedDB.

4. Despliegue en Dokploy (Docker & Traefik)

Variables requeridas en el archivo .env para producción:

NODE_ENV=production
TZ=America/Argentina/Buenos_Aires
PORT=3000
DATA_DIR=/data
BASE_URL=https://matafuegos.milicic.com.ar
CORS_ORIGIN=*
AUTH_PROVIDER=local

Volumen Persistente Obligatorio

En la configuración de la aplicación en Dokploy, montar el volumen: milicic_matafuegos_data ➔ /data. Esto asegura que la base de datos SQLite y los backups automáticos sobrevivan a cualquier redeployment o reinicio del host.

5. Respaldo y Restauración (Disaster Recovery)

# Ejecución de backup en caliente dentro del contenedor
docker exec -it <CONTAINER_ID> /app/scripts/backup.sh

# Restauración de un respaldo anterior
docker stop milicic-matafuegos
gzip -d /data/backups/matafuegos_backup_20261002.db.gz
cp /data/backups/matafuegos_backup_20261002.db /data/matafuegos.db
docker start milicic-matafuegos
